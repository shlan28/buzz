# 我用 Buzz 二开，搭建了 Agent Team

我一直希望有一个自己的 Agent Team。团队中的 Agent 可以有不同的分工，从不同视角帮我分析问题，协助处理日常工作，也能帮我安排和管理日程。

但我平时使用的 Codex、Claude Code 等产品，本质上都是一次与一个 Agent 协作。它们可以完成具体任务，却很难直接组成一个分工明确、持续协作的团队。

在寻找多 Agent 产品时，我发现了 Buzz。它本身支持多个 Agent、Channel 和团队协作，同时项目开放，可以根据自己的工作方式继续开发。因此，我选择在 Buzz 的基础上进行二次开发，把它改造成更适合自己的 Agent Team。

这次改造的目标不是简单增加几个 Agent，而是让它们更像真正的团队成员：既能管理工作安排，也能在合适的时候主动参与讨论。

这次改造主要包含两个功能。

## 一、让 Agent 使用日历

我为 Buzz 增加了完整的日历功能。现在可以在桌面端查看日、周、月视图，创建、编辑和删除日程，也可以分别查看个人与不同 Agent 的日历。

更重要的是，Agent 也能直接操作日历。它可以根据对话中的任务创建日程，查询已有安排，或更新和删除自己创建的日程。例如，当我让 Agent 安排一次项目复盘时，它可以直接创建对应的日历事件，不需要我再手动录入。

Agent 创建的日程会保留 Agent 自己的身份，我作为它的 Owner 可以在日历中查看。这样既能明确是谁创建了日程，也避免 Agent 代替用户操作个人日历。

为了让多个 Agent 的安排更容易管理，日历支持按来源筛选。个人日历和每个 Agent 的日历可以单独显示或隐藏；某个 Agent 的日历读取失败时，也不会影响其他日历继续使用。

## 二、让 Agent 在 Channel 中主动回复

Buzz 原来的 Channel 更接近常见群聊：只有明确 `@Agent`，Agent 才会收到消息并回复。这种方式适合偶尔调用工具，但不适合长期协作，因为每次交流都需要点名。

我修改了这个机制，并在 Agent 配置中增加了一个开关。开启后，只要我以 Owner 身份在该 Agent 所在的 Channel 中发言，即使没有 `@` 它，Agent 也能接收消息并回复。

这个配置属于具体的 Agent 实例，而不是一个通用的角色模板。因此，同一个 Channel 中可以有多个 Agent，但只有开启该功能的 Agent 会主动响应。这样可以按团队分工决定谁需要持续参与讨论，避免所有 Agent 同时回复。

主动回复仍然遵守原有边界：Agent 必须已经加入对应 Channel，只有经过验证的 Owner 可以免 `@` 触发，其他成员仍按原来的规则使用。Agent 的回复也会进入对应话题，不会打乱 Channel 的主消息流。

## 让手机也能连接本地服务

Buzz 服务运行在我的本地电脑上，默认只能通过 `localhost` 访问。这样在电脑上开发和使用没有问题，但手机无法直接连接。

为了解决这个问题，我接入了 Cloudflare Tunnel，把本地服务安全地转发到自己的域名。手机上的 Buzz Mobile 连接这个域名后，就能访问电脑上运行的同一套 Buzz 服务。

这意味着我不需要把整套服务部署到云服务器，也能在手机上查看 Channel、与 Agent 对话，并使用本地环境中的数据和功能。只要本地服务和 Tunnel 保持运行，Desktop 与 Mobile 就可以进入同一个协作空间。

## 从 Agent 工具到 Agent Team

这两个功能解决的是同一个问题：如何让 Agent 真正进入日常协作流程。

日历让 Agent 可以管理时间和计划，Channel 主动回复让 Agent 可以持续理解讨论并及时参与。两者结合后，Agent 不再只是等待命令的工具，而是有身份、有工作范围、能参与沟通的团队成员。

当然，主动并不意味着越多越好。如果多个 Agent 都对每条消息作出回应，Channel 很快会变得嘈杂。更合适的做法是为每个 Agent 明确职责，只给需要持续参与讨论的 Agent 开启主动回复。后续还可以增加团队协调者，由一个 Agent 判断任务应该交给谁，让 Agent Team 的协作更有秩序。
